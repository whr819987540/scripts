# Zsh 安装与配置步骤

`zsh_install.sh` 安装 Zsh 和 Git，安装或更新 Oh My Zsh 及三个插件，在 `~/.zshrc` 中写入受管配置块，最后尝试把 Zsh 设为默认 shell。

## 安装依赖

1. 检查 Zsh 和 Git 的版本。按 Oh My Zsh README 的建议，要求 Zsh 不低于 5.0.8、Git 不低于 2.4.11。

   ```bash
   zsh --version
   git --version
   ```

2. 安装缺失或版本过低的软件。Ubuntu/Debian 使用：

   ```bash
   sudo apt-get update
   sudo apt-get install -y zsh git
   ```

   对已安装的软件包执行安装会升级到包管理器提供的最新版本。脚本还支持 `dnf`、`yum`、`pacman` 和 Homebrew，只处理缺失或过旧的软件，处理后再次检查版本，仍不满足要求时报错退出（例如 CentOS 7 自带的 Zsh 5.0.2 和 Git 1.8.3）。

## 安装 Oh My Zsh 和插件

1. 安装 Oh My Zsh。目录已经是 Git 仓库时，执行 `git -C ~/.oh-my-zsh pull --ff-only` 更新。

   ```bash
   git clone --depth=1 https://github.com/ohmyzsh/ohmyzsh.git ~/.oh-my-zsh
   ```

2. 安装 Conda 补全插件。

   ```bash
   git clone --depth=1 https://github.com/conda-incubator/conda-zsh-completion.git \
       ~/.oh-my-zsh/custom/plugins/conda-zsh-completion
   ```

3. 安装命令建议和语法高亮插件。

   ```bash
   git clone --depth=1 https://github.com/zsh-users/zsh-autosuggestions.git \
       ~/.oh-my-zsh/custom/plugins/zsh-autosuggestions
   git clone --depth=1 https://github.com/zsh-users/zsh-syntax-highlighting.git \
       ~/.oh-my-zsh/custom/plugins/zsh-syntax-highlighting
   ```

   插件目录已经是 Git 仓库时，与 Oh My Zsh 一样使用 `git -C <插件目录> pull --ff-only` 更新。

## 配置并启用 Zsh

脚本不会覆盖整个 `~/.zshrc`。第 2～5 步的配置写在 `~/.zshrc` 中下面这对标记之间，重新运行脚本时只替换标记之间的内容，标记之外的个人设置保持不变：

```zsh
# >>> scripts zsh configuration (zsh_install.sh) >>>
...
# <<< scripts zsh configuration <<<
```

脚本按 `~/.zshrc` 的现状处理：

| `~/.zshrc` 的现状 | 处理方式 |
| --- | --- |
| 已有这对标记 | 只替换标记之间的内容 |
| 不存在或为空 | 新建，内容为配置块 |
| 由旧版脚本整份生成（首行是 `# Generated by https://github.com/whr819987540/scripts/blob/main/zsh_install.sh`） | 替换为配置块；旧版脚本本来每次运行都整份覆盖这个文件 |
| 在标记之外已经加载 Oh My Zsh | 不修改，提示迁移步骤，避免 Oh My Zsh、Conda、nvm 被加载两次 |
| 其他内容 | 把配置块插到文件开头，原有内容放在后面，可以覆盖配置块中的设置 |
| 标记不成对或重复 | 报错退出，不修改 |

内容有变化时，脚本先把原文件备份为 `~/.zshrc.backup.<时间戳>`。

配置块直接写在 `~/.zshrc` 中，而不是放到单独的文件再 `source`，这样 nvm 安装器在 `~/.zshrc` 中能找到 `/nvm.sh`，不会再追加一份 nvm 加载代码。

1. 不是旧版脚本生成、但已经在标记之外加载 Oh My Zsh 的 `~/.zshrc` 需要手动迁移：先移开旧文件，重新运行脚本生成配置块，再把旧文件中的个人设置复制到配置块下方。

   ```bash
   mv ~/.zshrc ~/.zshrc.old
   source <(curl -fsSL https://gitee.com/hit_whr/scripts/raw/main/run.sh) zsh
   ```

2. 在配置块中设置主题和插件。

   ```zsh
   export ZSH="$HOME/.oh-my-zsh"
   ZSH_THEME="robbyrussell"
   zstyle ':omz:update' mode disabled
   plugins=(git extract conda-zsh-completion zsh-autosuggestions zsh-syntax-highlighting)
   source "$ZSH/oh-my-zsh.sh"
   ```

   加载 Oh My Zsh 之后定制 robbyrussell 的提示符：显示 `用户@主机`、从 `~` 开始的完整路径，Git 分支显示为 `(main*)`，例如 `(base) whr@host ➜  ~/code (main*)`。提示符写在配置块里，不修改 Oh My Zsh 的主题文件，以免更新 Oh My Zsh 时冲突。这段放在 Conda 之前，Conda 才能在前面加上环境名：

   ```zsh
   PROMPT="%{$fg[yellow]%}%n@%m %{$reset_color%}%(?:%{$fg_bold[green]%}%1{➜%} :%{$fg_bold[red]%}%1{➜%} ) %{$fg[cyan]%}%~%{$reset_color%} "
   PROMPT+='$(git_prompt_info)'
   ZSH_THEME_GIT_PROMPT_PREFIX="%{$fg_bold[blue]%}(%{$fg[red]%}"
   ZSH_THEME_GIT_PROMPT_SUFFIX="%{$reset_color%} "
   ZSH_THEME_GIT_PROMPT_CLEAN="%{$fg_bold[blue]%})"
   ZSH_THEME_GIT_PROMPT_DIRTY="*%{$fg_bold[blue]%})"
   ```

3. 按需在配置块中加载 Conda、个人环境变量、Homebrew、Clash、NVM 和 Rust 环境。脚本会检测对应文件或命令，仅加载已安装的组件。

   Conda 与 `conda init` 一样通过 hook 初始化，是否自动激活 base 由 conda 自己的 `auto_activate_base` 设置决定。新的 shell 里 conda 还不在 PATH 上，所以脚本会依次查找 PATH、`~/miniconda3` 和 `~/anaconda3`：

   ```zsh
   eval "$("$HOME/miniconda3/bin/conda" shell.zsh hook)"
   ```

   个人环境变量文件 `~/.env_var` 在 Conda 之后加载，以便覆盖 Conda 的设置；它可能包含密钥，不要提交到仓库。

   Homebrew 会把自己的 `bin` 目录插到 PATH 最前面。zsh 不读取 `~/.profile`，所以要在 Homebrew 之后把 `~/.local/bin` 放回最前面，让交互式 zsh 与非交互 shell 使用同一个 `~/.local/bin/tmux`：

   ```zsh
   typeset -U path PATH
   path=("$HOME/.local/bin" $path)
   ```

4. 在配置块中配置历史记录，使历史在 shell 退出时追加，并避免多个终端实时共享。

   ```zsh
   HISTFILE="$HOME/.zsh_history"
   HISTSIZE=10000
   SAVEHIST=10000
   setopt APPEND_HISTORY EXTENDED_HISTORY
   unsetopt SHARE_HISTORY INC_APPEND_HISTORY INC_APPEND_HISTORY_TIME
   ```

5. 在配置块末尾清理终端的残留状态。tmux、vim 等全屏程序没有正常退出时（例如 SSH 断线），终端可能留在两种状态里：
   - 鼠标上报仍开着：移动或点击鼠标会在提示符里打出转义序列。
   - 仍在备用屏幕（alternate screen）：备用屏幕没有 scrollback，终端会把滚轮转成上下方向键，滚轮于是翻的是历史命令而不是输出。

   `\e[?1049l` 在已经处于普通屏幕时也会把光标恢复到上次保存的位置，提示符会跳行，所以前后用 `\e7`/`\e8` 保存并恢复光标，正常登录时光标不动。只在交互式 shell 且标准输出是终端时执行，`zsh -i -c ... | ...` 这类管道不受影响：

   ```zsh
   if [[ $- == *i* && -t 1 ]]; then
       printf '\e[?1000l\e[?1002l\e[?1003l\e[?1005l\e[?1006l\e[?1015l'
       printf '\e7\e[?1049l\e8'
   fi
   ```

6. 将 Zsh 设为默认 shell，并启动新 shell。

   ```bash
   chsh -s "$(command -v zsh)"
   exec zsh
   ```

   当前登录 shell 已经是同一个 zsh 文件时（包括 `/bin/zsh` 与 `/usr/bin/zsh` 指向同一文件的情况），脚本跳过 `chsh`。

也可以通过统一入口一次完成。脚本写入的配置块还包含第 3 步所述的可选组件检测：

```bash
source <(curl -fsSL https://gitee.com/hit_whr/scripts/raw/main/run.sh) zsh
```
